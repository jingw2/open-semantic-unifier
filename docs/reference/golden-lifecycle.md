# Golden 生命周期执行步骤

版本 1.0。此文件解释 `tests/golden/v1/lifecycle.json`。这是未来产品集成测试的合同，当前状态全部为 NOT_RUN。

## 通用环境

每项在独立项目、干净数据库事务或隔离部署中运行。导入相应 domain 的 records 与 scheme。除明确调用人工裁决的步骤外，不把 expected 真值传给应用。实体 ID 使用首次响应绑定的符号 `E1/E2` 表示，不写死具体 UUID。

每次操作记录真实 API 请求、响应、数据库约束、版本及业务审计。失败时保留观察值；不得用测试替身替代实体存储和裁决逻辑。受控模型 HTTP 服务仅用于确定性地注入超时、坏 JSON 和不同建议，不用于宣称真实模型质量。

## 文件批次 API

`POST /api/v1/projects/{project_id}/unification/batches/file` 接收 multipart 表单：`file` 为 UTF-8 CSV（首行是列名）或 Parquet 文件；`input_version`、`source_system`、`dataset`、`source_key_column` 指定输入版本和来源键；`mode` 可为 `sync`（默认）或 `exploration`。指定的键列从属性中排除，其余列作为属性。CSV 的列值按文本读取；Parquet 的键列必须为字符串类型，以保留 `001` 这样的标识。同步模式缺键或同批键重复时整个批次拒绝，响应沿用 JSON 批次的逐行错误格式。该接口需要项目 editor 或 admin 权限。
