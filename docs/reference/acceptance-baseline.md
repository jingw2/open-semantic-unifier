# Open Semantic Unifier 验收基线

版本：1.0。确认日期：2026-11-23。状态：范围已确认，V0.1 验收已执行；逐项证据见 [acceptance-status.json](acceptance-status.json)。合并和部署仍需单独授权。

本文件是实施计划和 Golden Test Set 的需求来源。增加能力必须先说明对应的用户任务和验收证据。修改已确认行为需要记录变更原因，不能通过降低测试要求让实现通过。

## 用户与交付范围

首批用户是整合多个业务系统的小型数据团队。首阶段成功标准是外部用户不修改源码，完成自己的实体统一任务。供应商、客户、商品是三个公开案例，核心逻辑通过字段、规则和实体粒度配置支持更多场景。

首版以 Web 工作台为主要入口，核心操作同时提供 API。输出统一实体表、来源映射、匹配和裁决历史、本次变化。支持 CSV、Parquet、JSON 批量 API，以及逐个验证的数据库批量接入。不写回来源系统。

不要求接入外部模型才能执行基础规则。用户可连接本地或私有化的模型接口；首版不建设数据隐私治理系统。凭据不进入日志和 trace，既有工作空间隔离必须保留。Phoenix 是可选运行服务，但可用的追踪集成是发布验收要求。

暂缓 CDC、实时双向同步、独立 SDK、CLI、自研观测平台。L3/L4 暂列实验功能，不作为实体统一首版已完成的能力。

## 业务语义

- 实体身份在项目和实体类型内有效。供应商案例按法人，客户按人，商品按可售规格识别。集团关系、家庭关系和商品相似不是实体相等。
- 来源键是 `(project_id, source_system, dataset, source_record_id)`。不同来源中的 `001` 是不同记录。
- `AUTO_MATCH` 表示规则允许自动确认；`REVIEW` 表示需要复核；`DISTINCT` 表示本方案明确拒绝合并。低相似度和缺少候选不能自动变成永久拒绝。
- 真值 `SAME / DIFFERENT / UNRESOLVED` 与动作分开。真实为 SAME 的记录仍可能必须 REVIEW。
- 人工禁止合并和配置的冲突约束优先于模糊分数及模型判断。传递聚类不能绕过禁止关系。
- 缺失、空串不作为相等的身份标识。号码、邮箱和普通名称默认不是可信唯一标识。
- 人工裁决作用域、原因、操作者和版本必须保留。源数据变化使旧裁决依据失效时，产生显式冲突并重新复核，不静默套用。
- 合并保留一个有效实体 ID，退役 ID 保留可追踪重定向。拆分记录成员归属及前后身份关系。重定向无环；历史版本解释历史身份。
- 标准属性有独立选择规则。来源优先级、人工覆盖、其他来源值及冲突均可查询。
- 已发布快照不可变。修正、重新发布和回滚只改变显式版本或当前发布指针。

## Golden 数值规则

公开集是开发回归基线，不是生产总体准确率证明。每个场景单独通过，不能让平均值掩盖某个场景失败。

1. 30 组案例的预期动作全部一致。
2. 所有 `required_candidate=true` 的配对均被召回。
3. 已知 DIFFERENT 的配对最终错误合并数为 0。
4. 初始运行只允许预期 AUTO_MATCH 的配对共用实体。其他未获允许的聚类链接数为 0。
5. 所有预期 AUTO_MATCH 的配对必须实际合并。全单例、全送审不能通过。
6. 报告复核数量、已知 SAME 的数量和未合并数量。未合并的 SAME 包括有意送审，不将它误称为算法漏匹配。
7. 22 项生命周期单独执行并提供业务断言证据。配对评分器不执行这些测试。

公开集后续增补真实用户授权样本与独立留出集，先锁定数据和评估协议，再制定真实场景的准确率、吞吐及规模承诺。本版本不虚构性能门槛。

## 证据格式

每项执行记录包括 `baseline_id`、`status`、`git_commit` 加工作树 diff 标识、`golden_version`、环境和依赖版本、命令、输入引用、实际断言、输出报告路径、执行时间。模型实验另记 provider/model/prompt_version、可得参数及 trace 引用。

`BLOCKED` 必须说明缺少的外部条件。未接真实模型、未启 Celery 或未实际查询 Phoenix 时，对应项不得写 PASS。禁止将评分器自测、健康检查、构建成功替代业务验收。
